- **RPC responses MUST NOT be dropped.** `readPump` processes RPC synchronously in `web.go`. The old code used `select { case sendCh <- msg: default: drop }` for RPC responses. During `plugin_reload_all`, multiple widget pushes (`PushPluginWidgetsPerSession`) can fill `sendCh` (64 buffer) while the RPC handler runs. When the handler completes, its response hits a full `sendCh` and gets silently dropped → client blocks until 30s timeout. Fix: block with `time.After(10s)` instead of `default` drop. Also `writePump` must set `SetWriteDeadline(30s)` on all `WriteJSON` calls — without it, network back pressure causes `WriteJSON` to block indefinitely, freezing `writePump` so `sendCh` never drains.

- **Rendered iterations must be CONTIGUOUS (linear-consistency guard).** On a weak network an iteration's delta can be dropped before `restoreActiveProgress` backfills it (SSE stateless coalescing / buffer drops). `appendIterations` deduped by iteration number and `assertIterationContinuity` only logged — the UI rendered iteration 3 in place of the missing 2 (1, 3), violating linear consistency. - **loadMore (scroll-to-top pagination) MUST scroll-anchor the viewport via ΔscrollTop==ΔtotalSize, NOT anchor-row scrollToIndex.** Prepending older rows grows scrollHeight; without anchoring the viewport flashes to the top then jumps back. The old anchor-row approach (record first visible row id → `getOffsetForIndex` → `scrollToIndex`) needed double-rAF + retries to wait for ResizeObserver to measure the prepended rows — during that window the viewport flashed to top (user report: "加载历史后瞬间移到最上方再移回最下方"). Correct fix: before `onLoadMore()` snapshot `scrollTop` + `virtualizer.getTotalSize()`; after the prepend, in a **useLayoutEffect** (synchronous, before paint) apply `el.scrollTop = prevScrollTop + (newTotalSize - prevTotalSize)`. The prepend rows are estimated-height at that point; the residual error is corrected by TanStack's `shouldAdjustScrollPositionOnItemSizeChange` (configured to only adjust items FULLY above the viewport). Result: visible content is pixel-stable, older rows appear ABOVE the viewport — "data just got more", never a jump.
