# Web Message Annotations

First version (2026-10-09): comment on assistant body text, including streaming output, not a private-note system.

## Ownership And UI

- `AgentPanel` owns one keyed `MessageAnnotationsProvider` per login username and channel/chat, inside its stable panel root. Never wrap the observed root in the keyed provider: session changes would detach the element watched by IntersectionObserver, pausing the new chat's rendering notifications. Actions and draft contexts are separate: adding draft items does not invalidate every virtual message row.
- `CopyTarget` declares source hints on `data-annotation-source`; the provider observes native `selectionchange` within its own `display: contents` root. Selection endpoints must both be inside one `data-annotation-body`; cross-iteration/cross-panel selections are ineligible. Reasoning/tools/user bodies never set an eligible source. `LiveIteration` marks its text body and declares the actual turn/iteration; completed iterations inside an active turn may also be annotated.
- Streaming selection (user correction, 2026-10-09): capture the quote/offsets on selection completion. Typewriter frames clip directly from cached source text and change only the suffix of each text node, preserving native ranges in the already visible prefix. Never restore the full node before clipping: assigning `text.data` resets Range offsets even for identical text. A new Markdown parse still remounts nodes, which can collapse the native range and emit `selectionchange` without user input. For `data-annotation-live` bodies, those automatic events must not replace or dismiss the captured quote/action. A new pointer/keyboard gesture can replace or dismiss it; scroll/Escape/panel hiding still dismiss. Never freeze rendering, disconnect SSE or cancel the run to preserve a selection.
- Selection completion shows one 44px comment icon near the visible end of the selection, clamped to the visual viewport. Dragging does not show the icon until pointer-up; keyboard/native-touch selections use the same path. Events are coalesced with `frameScheduler`, with one observer per visible panel and no per-row document listeners. Scroll, custom copy menus, Escape, resize, collapse or panel hiding clears the icon; native touch `contextmenu` keeps it available (it may arrive after `selectionchange`). The icon preserves selection on pointer-down; the editor snapshots only the selected quote and never silently changes it through selection inside the quote field.
- Eligible touch body text allows native selection instead of the custom long-press copy timer. Tools, user messages and links retain their custom copy/link menus. Comment actions have been removed from right-click menus (user correction, 2026-10-09).
- The editor and list live outside virtual rows, using body portals. Desktop uses a collision-aware virtual-anchor Popover; mobile uses a Dialog sheet with its own `useKeyboardInset`. No persistent assistant action toolbar. Touch item actions use one ellipsis menu with 44px targets.
- Editor/list chrome omits turn/iteration source labels and character counters (user correction, 2026-10-09). Source locations are included in the model-visible XML prompt, but the sent-message bubble still displays only the body, quote and comment. Size limits still reject oversize content.
- Confirm adds a structured `{id, source, quote, comment}` to localStorage. It never calls the agent or changes Tiptap content. Composer capture restores the existing editor selection/focus after the overlay closes, unless the document changed during editing (then the latest selection wins).
- Confirmed drafts use `xbot:annotations:` plus a JSON tuple of username and channel/chat. Auth cache reset clears them. Auth epochs prevent a late acceptance from recreating an old identity's cache. Unconfirmed edits are kept while the owning provider remains mounted, but are not persisted.

## Sending

- `canSend = body || completed attachments || annotations`; the same predicate governs busy Send/Cancel branching. Uploads or an in-flight submission block repeat submits; an empty busy composer can still cancel during an upload.
- An open editor requires confirmation/cancellation before sending. In the comment field, Enter confirms locally (Ctrl/Cmd+Enter also works); Shift+Enter inserts a newline. IME composition/229 and repeated keydown never confirm, and empty comments are ignored. Confirmation consumes the key event and never sends the message. The mobile keyboard advertises a Done action. Existing composer send-key/IME guards remain authoritative.
- Annotation feedback rejects commands, goal mode and interject mode. One normal message starts with `# Response annotations:` and a localized instruction distinguishing historical quotes from current comments, followed by a `<response-annotations>` XML element containing a JSON array of `{text, annotation, source}`. `# My request:` contains the unchanged composer body. Attachment references still use the original upload protocol. JSON serializes strings and escapes `<`, `>` and `&` as Unicode escapes, preserving the quote/comment on decoding without allowing an embedded closing tag or XML entity to alter the envelope.
- The serialized source uses `turnId`, `iteration`, `messageId` when known and `startOffset`/`endOffset` captured from the actual selection. Offsets are zero-based, half-open UTF-16 positions into the selected body's concatenated DOM text (`offsetBasis: "dom-text"`, `offsetEncoding: "utf-16"`), not raw Markdown positions. The capture uses DOM ranges, not `indexOf(quote)`, so repeated text, nested Markdown elements, emoji and backwards selection retain the selected occurrence. Native selection quotes may contain visual line breaks that do not contribute to DOM offsets. Old local drafts without offsets remain readable; no offset or message ID is invented for them.
- No new Go transport/storage field, backend delimiter parsing or user-history prewrite. Normal REST/WS ingress, queue, eager agent persistence, history and model replay all carry the same XML prompt string. `UserMessage` alone decodes complete envelopes for display using DOMParser + JSON.parse + shape/limit validation. It renders quote/comment snapshots with literal fences, keeping HTML, links, math and commands inert in those snapshots; copy and rewind/edit retain the original XML content. Ordinary XML examples, old Markdown feedback and malformed envelopes are not transformed. Notification rendering remains unchanged. This is compatible with the existing server, not a new structured server annotation protocol.
- `useChatMessages.sendMessage` returns `Promise<boolean>` for ingress acceptance; `AgentPanel` returns it to `MessageInput`. Failure retains editor, attachments and annotations. Success removes only the submitted annotations; body clears only if its revision has not changed, and newly added attachments are preserved. Successful acceptance is not a claim that the queued message is already persisted/read.
- Within a mounted composer, unchanged retries reuse the annotation request ID. Server deduplication is still the existing in-memory 10-minute mechanism, not durable exactly-once across restart/refresh. Do not claim that uncertainty has been fully solved.

## Limits And Deliberate Boundaries

At most 10 items; quote <=6000 code points, comment <=2000, total <=20000. Never truncate. These are product character limits, not token estimates.

The agent sees both quote snapshots and the available source locations. The source is a selection-time hint, not a permanent anchor: rewind can reuse turn/iteration numbers. No source lookup, cross-session read, raw Markdown offset mapping, hashes, source highlights, automatic reattachment after rewind or reply-link directives. No server/CAS/cross-device drafts, dedicated collapsible annotation history cards, private notes, or restoring cancelled queue items as structured annotation drafts. The design PRD describes those possible later capabilities; it is not the shipped contract.

## Verification

Focused unit tests: `messageAnnotations.test.ts`, `MessageAnnotations.test.tsx`, `MessageActions.test.tsx`, `MessageInput.test.tsx`, `UserMessage.test.tsx`; send acceptance regression checks in `useChatMessages.test.ts` and observed panel-root stability in `AgentPanel.test.tsx`. Includes XML/JSON round-trip, hostile embedded tags, source validation, missing legacy offsets, source-free display and original XML copy/edit. `e2e/region-window.spec.ts` protects region loading and tool-detail hydration through this provider integration.

Browser checks: `e2e/message-annotations.spec.ts` uses mocked sessions and ingress; no writes to the user's paused AskUser chat. It covers real desktop mouse drag (without right-click), exact selected quote, Enter confirmation without sending, real Shift+Enter newlines, IME guards, minimal editor/list chrome, add/edit/refresh/send, the exact submitted XML source fields, repeated Markdown selection with an emoji prefix/backwards selection, source-free display after history reload, annotation-only busy failure retention, attachment/rich-text preservation, session isolation, and mobile native-selection CSS/no custom long-press interception/simulated keyboard inset/item deletion. Programmatic selection helpers first click the body to blur Tiptap as native selection would, so the focused editor's DOM observer cannot overwrite the range. Mobile selection handles are simulated, not an OS-level handset test. Existing `msg-actions.spec.ts` protects copy/link menus.

Continuous-output cases emit incremental SSE through the real provider/state-machine/typewriter path, dispatching only to open mocked connections. Both completed-body selection and real mouse selection of live text must retain the original quote/source through subsequent frames, editing, confirmation, preview and queued submission; each step asserts the next frame appears and no cancel request is sent. The long-reply regression selects numbers 109 through 124 across lines without waiting for the current typewriter animation to finish, opens a comment and verifies output continues to 1000 without replacing the quote. `MarkdownRenderer.test.tsx` also advances visible characters deterministically with a native Range selected in a fully or partially revealed node, including restoration when streaming ends. Static `busy=true` alone is not evidence of uninterrupted streaming.

To record the desktop demonstration, use `XBOT_RECORD_ANNOTATIONS=1 npm run test:e2e -- e2e/message-annotations.spec.ts --grep 'Enter confirms' --retries=0 --timeout=45000 --workers=1 --output=output/playwright/annotations-enter`. Recording is opt-in; only the recording run adds viewing pauses. It captures the existing xbot UI and mocked ingress, not a standalone design mockup or a real agent request.

Full frontend verification (run from `web/`): `npm test`, `npm run lint`, `npm run build`, and `npm run test:e2e -- e2e/message-annotations.spec.ts e2e/msg-actions.spec.ts --workers=1 --retries=0`. On Node 26, use `NODE_OPTIONS=--no-experimental-webstorage npm test` so jsdom owns `localStorage` rather than Node's unconfigured native storage getter. No dependency or product runtime change is needed.
