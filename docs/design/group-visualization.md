# Agent 通信指挥室（Group Visualization）

> 版本：v1.0（2026-10-19）
> 配套实现：主库 v74（`groups`/`group_members`）、会话库 v4（`group_id`/`sender_*` 列 +
> `ix_sm_group_cursor`）、`/api/groups*`、`group.message` 事件、Web 面板 `CourtConsole`。
>
> 本文只解决一件事：**把「谁在什么时候、因为什么、向谁、发了什么、对方回了什么」
> 画成一张可读的图**。群组语义（群发=遍历成员各发一份、各写各的会话库）不在这里
> 重新设计，参见 `group-hardening.md` 与 `court-orchestration.md`。

---

## 0. 一句话结论

组织树回答「谁归谁管」，指挥室回答「谁在跟谁说话、说到哪一步、卡在谁那里」。
前者是**静态结构**，后者是**动态通信**；把通信硬塞进组织树，会同时丢失时间、方向、
扇出和阻塞关系。因此主视图必须是**泳道时间轴 + 弧线消息流**，组织树只做左侧过滤器。

## 1. 五个视图

| # | 视图 | 回答的问题 | 实现形态 | 是否首屏 |
|---|---|---|---|---|
| ① | 泳道时间轴 + 弧线消息流 | 什么时候、谁发给谁、什么类型、是否卡住 | Canvas 2D（可降级 WebGL） | ✅ 主视图 |
| ② | 左侧组织树 | 群里有谁、什么状态、当前任务与进度 | DOM 树 + CSS 状态灯 | ✅ 常驻 |
| ③ | 线程视图 | 一个问题从提出到闭环经历了哪些消息 | DOM 折叠面板（correlation_id 分组） | 右侧详情 |
| ④ | Sankey 宏观流量 | 哪个部门/agent 之间流量最大、是否单向 | SVG 贝塞尔带（d3-sankey 数据形状，手写渲染） | 底部可切换 |
| ⑤ | 时间回放 | 过去 N 小时/天事情是怎么演进的 | 滑块 + 1x/10x/100x + 光标推进 | 顶部工具栏 |

### 1.1 主视图：泳道时间轴（为什么是它）

- **X 轴 = 时间**，可缩放（滚轮/双指）、可平移（拖拽）。时间是最强的叙事轴：
  早会、午间故障、深夜复盘天然分段。
- **Y 轴 = 参与者泳道**（owner + 每个 agent）。泳道不是组织层级，而是「说话的位置」。
- **消息 = 从发送者泳道到接收者泳道的贝塞尔弧线**：
  - 单发：一条弧线；
  - 群发/扇出：同一 `message_id` 拆成多条弧线，共享起点、终点分散，形成「束」；
  - 自问自答（agent 内部动作）：小回环，不跨越泳道。
- **弧线颜色 = kind**（见 §5.1）。悬停高亮整条线程，点击打开右侧详情。
- **未回答的 ask_user**：目标泳道上的消息点做呼吸脉冲（2s 周期，透明度 0.35→0.9），
  并在顶部「待回答」计数里累加。
- **流动动画**：沿弧线运动的 2–3 个光点，速度与消息「新旧」相关；回放模式下由
  回放光标统一驱动，暂停时静止。

### 1.2 左侧组织树

- 节点：owner（首辅）→ 部门 agent（户部/工部/吏部）。成员地址解析
  `agent:<role>/<instance>`，显示 role 中文名 + instance。
- 状态灯三态：
  - 绿 `alive + idle`：最近 5 分钟无消息；
  - 黄 `alive + busy`：有未回答 ask_user 指向它，或最近一条消息是它发出的；
  - 灰 `left`：`group_members.status='left'`。
- 当前任务：该 agent 最近一条 `report`/`action` 的 `payload.summary` 截断。
- 进度条：该 agent 在本群中「已闭环线程 / 总线程」的比例（correlation_id 维度）。
- 点击节点 = 过滤：只显示与该 agent 相关的消息（发送或接收），再次点击取消。

### 1.3 线程视图（correlation_id 折叠）

一条线程 = 同一 `correlation_id` 的消息按时间排序：

```
decision（首辅：今日议题）
  → ask_user（首辅 → 户部：是否扩容？）
    → answer（户部：暂不扩容）
      → report（户部：指标）
        → decision（首辅：准）
          → action（户部：已更新看板）
```

- 默认折叠成一行摘要：`议题标题 · 6 条 · 42 分钟 · 已完成`；
- 展开后逐条显示 sender / kind 徽标 / 时间 / content；
- 未闭环线程（最后一条是 ask_user 且无 answer）标红并置顶。

### 1.4 Sankey 宏观流量

- 节点 = 参与者（左列发送、右列接收，或按部门聚合）。
- 带宽 = 时间窗口内的消息条数（可按 kind 过滤）。
- 时间窗口：15 分钟 / 1 小时 / 6 小时 / 全天 / 全部（默认全天）。
- 交互：hover 高亮对应链路与原始消息；click 把该链路加入主视图过滤。

### 1.5 时间回放

- 底部滑块覆盖 `[最早消息, 最新消息]`；
- 播放速度 1x / 10x / 100x（1x = 真实时间，10x 表示 1 秒推进 10 秒）；
- 回放时主视图只渲染 `ts <= cursor` 的消息，弧线按「已发生」淡入；
- 暂停可拖动定位；「回到最新」一键退出回放。

## 2. 为什么树形图不够（组织图 vs 通信图）

| 维度 | 组织树 | 通信图（指挥室） |
|---|---|---|
| 语义 | 汇报关系（静态） | 消息流向（动态） |
| 时间 | 无 | X 轴，可缩放/回放 |
| 方向 | 父子 | 任意 A→B，含扇出与回环 |
| 阻塞 | 看不出来 | 未回答 ask_user 脉冲 + 线程置顶 |
| 频率 | 看不出来 | 弧线密度 / Sankey 带宽 |
| 多线程 | 一条汇报线 | 多条 correlation_id 并行 |
| 跨部门协同 | 需要展开多层 | 一条弧线直达 |

具体反例：

1. **工部 → 户部** 的临时切流协同与汇报关系无关，组织树里只能画成「兄弟节点」，
   看不出这是一次故障处置。
2. **首辅群发** 给三个部门：组织树要么画三条重复的父子线，要么只画一条（丢失扇出）。
3. **ask_user 卡住**：组织树只能标注「户部 busy」，但看不出它在等谁回答、等了多久。
4. **时间回放**：组织树没有时间维度，无法回答「昨天下午三点谁在跟谁说话」。

结论：组织树保留为**过滤器/图例**，主画布必须是通信图。

## 3. 数据来源

### 3.1 消息信封（会话库 `session_messages`）

| 字段 | 类型 | 用途 |
|---|---|---|
| `id` | INTEGER | 时间轴排序、keyset 游标 |
| `group_id` | TEXT | 群过滤（`ix_sm_group_cursor(group_id, id DESC)`） |
| `sender_type` | TEXT | `agent` / `user` / `system`，决定头像与泳道归属 |
| `sender_id` | TEXT | `hubu/main` / `web-1`，泳道 key |
| `sender_name` | TEXT | 可读名（户部 / 首辅） |
| `content` | TEXT | 消息正文 / 卡片摘要 |
| `record_data` | TEXT(JSON) | 信封：`kind`、`correlation_id`、`to[]`、`payload{}` |
| `created_at` | DATETIME | 时间轴定位 |

> 设计取舍：`kind`/`correlation_id`/`to`/`payload` 放进 `record_data`，不新增 4 张表。
> 它们只服务展示，不参与 LLM 上下文；`record_data` 本来就有「结构化展示元数据」语义。

### 3.2 群组元数据（主库）

- `groups(id, name, owner, created_at)`
- `group_members(group_id, member_addr, status, joined_at)`，`status ∈ {alive,left}`

### 3.3 state 文件（可选增强）

若 agent 侧存在 `court/state/departments/*.yaml`，前端可读取其中的 `status`/`progress`
作为组织树的**权威覆盖**；缺失时退化为「从消息推导」：

- busy = 有未回答 ask_user 指向该 agent；
- progress = 已闭环线程数 / 相关线程数；
- current_task = 最近一条 report/action 的 payload 摘要。

这样即使 state 文件不存在，面板仍可用（真实 API 数据 + 推导状态），不出现空白。

### 3.4 读取路径

```
GET /api/groups                                   → 群列表（owner/alive 成员可见）
GET /api/groups/{id}/members                      → 成员 + 派生 name/role/instance
GET /api/groups/{id}/messages?cursor=&limit=50    → 当前会话视角，keyset 分页
     &channel=web&chat_id=court-demo              → 显式会话视角（仍走 canAccessSession）
POST /api/groups                                  → 建群（演示）
POST /api/groups/{id}/members                     → 加成员（演示）
POST /api/groups/{id}/messages                    → 追加消息 + group.message 事件（演示）
```

**权限**：消息读取要求调用者是 owner 或 `alive` 成员；显式会话视角还要通过
`resolveAPISession → canAccessSession`。绝不跨会话库聚合。

**实时**：`group.message` 事件经现有 WS/SSE 通道广播，payload 为
`{group_id, message}`；不重放，断线后用 REST 按游标补齐。

## 4. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 时间轴/弧线 | **Canvas 2D**（`requestAnimationFrame`） | 数百～数千条弧线仍能 60fps；比 SVG DOM 节点少两个数量级；无需 WebGL 的兼容成本 |
| 缩放/平移 | 自研 `viewport{scale, offsetX, offsetY}` + 滚轮/指针事件 | 时间轴只需要 2D 仿射变换，d3-zoom 会引入完整 D3 依赖 |
| 时间比例尺 | 手写线性 scale（`d3-scale` 同公式） | 时间范围固定、均匀刻度，线性足够；避免为 20 行代码引入依赖 |
| 组织树 | **DOM + CSS** | 可访问性、点击/hover、文本截断天然可用；节点数 < 50 |
| 线程面板 | DOM 折叠 | 文本/徽标/滚动，不需要画布 |
| Sankey | **SVG path**（手写二次贝塞尔带） | 链路 < 100，SVG 的 hover/aria 更简单 |
| 状态管理 | React `useState`/`useMemo` + 一个 `useCourtData` hook | 数据量小；无需引入状态库 |
| 实时 | 现有 `/api/events` SSE + `group.message` | 复用鉴权/重连/多路订阅，零新通道 |

**性能预算**：首屏 ≤ 2,000 条消息；超过后按「可视时间窗」裁剪。Canvas 每帧只画
可视窗口内弧线，离屏消息不参与绘制。

## 5. 视觉规格

### 5.1 kind 配色（深色主题）

| kind | 语义 | 主色 | 弧线样式 |
|---|---|---|---|
| `ask_user` | 提问/等待回答 | `#f5a524` 琥珀 | 实线 + 目标端脉冲 |
| `answer` | 回答 | `#22c55e` 绿 | 实线 |
| `report` | 汇报 | `#38bdf8` 天蓝 | 实线，稍粗 |
| `decision` | 决策 | `#a78bfa` 紫 | 实线 + 菱形端点 |
| `action` | 动作/执行 | `#f472b6` 粉 | 虚线 |
| `text` | 普通消息 | `#94a3b8` 灰蓝 | 细实线 |

### 5.2 状态色

- `busy` 黄 `#f5a524`，`idle` 绿 `#22c55e`，`blocked` 红 `#ef4444`，`left` 灰 `#64748b`；
- 泳道背景：busy 5% 黄、blocked 6% 红、idle 透明；横向色带贯穿整条泳道。
- 朝会时刻：每天 09:00 一条竖向虚线 + 顶部小旗标。

### 5.3 动效

- 弧线入场：`stroke-dashoffset` 从全长到 0，180ms；
- 流动光点：沿弧线 2 个点，周期 3s，透明度 0.5；
- ask_user 脉冲：`scale 1→1.6`、`opacity .9→0`，2s `ease-out` 循环；
- 视图切换：200ms 淡入，不做位移动画（避免时间轴错位感）。

### 5.4 布局与响应式

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：群选择 · 时间范围 · 播放控制 · 待回答计数 · 视图切换      │
├──────────┬───────────────────────────────────┬───────────────┤
│ 组织树    │ 主画布（泳道时间轴 / Sankey）       │ 详情/线程      │
│ 220px    │ flex-1                            │ 320px         │
├──────────┴───────────────────────────────────┴───────────────┤
│ 底部：回放滑块 + 缩放提示 + 图例                              │
└──────────────────────────────────────────────────────────────┘
```

- `< 1100px`：右侧详情改为抽屉（点击消息滑出）；
- `< 760px`：组织树折叠为顶部横向头像条；
- 深色主题为默认；所有颜色用 CSS 变量，便于主题切换。

### 5.5 空态 / 错误态

- 无群：居中插画 + 「创建演示群」按钮（调用 `POST /api/groups`）；
- 有群无消息：显示「该会话视角暂无群消息」+ 当前会话 selector + 刷新按钮；
- API 失败：顶部红色条 + 错误文本 + 「使用演示数据」按钮（前端内置 seed 兜底）；
- WebSocket 断开：顶栏黄点 + 「实时暂停，正在重连」，REST 数据仍可浏览。

## 6. 交互规格

| 操作 | 结果 |
|---|---|
| 滚轮 | 以指针位置为锚点缩放时间轴（0.5x–20x） |
| 拖拽画布 | 平移时间轴；纵向拖拽固定（泳道不滚动） |
| 双击画布 | 缩放到「该时间点 ±5 分钟」 |
| hover 弧线 | 高亮该消息 + 同 correlation_id 线程；tooltip 显示 sender→to、kind、时间 |
| click 弧线 | 右侧详情打开；线程视图定位到该消息 |
| click 泳道标签 | 过滤该 agent（再点取消） |
| 空格 | 播放/暂停回放 |
| `+` / `-` | 放大/缩小 |
| `Esc` | 关闭详情/退出回放 |

## 8. 已知边界（实现层）

1. **一个会话库一个视角**：`GET /messages` 读调用者当前会话库，不做跨库聚合；
   群主看「自己的群发 + 各自回奏」，成员看「收到的 + 自己的回复」。
2. **实时事件不重放**：断线重连后靠 REST 游标补齐；事件与库之间可能有一瞬重复，
   前端按 `message.id` 去重。
3. **状态推导是启发式**：busy/进度在无 state 文件时由消息推导，不是权威调度状态。
4. **回放只回放消息**：不回放 agent 的中间推理/工具调用（那些不在群消息信封里）。
