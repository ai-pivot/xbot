# Orchestrator — 主 Agent 指挥模式

主 agent 的时间只能花在**只有主 agent 能做**的事上：定方向与方案、跨线索综合、独占资源实验、最终实现。其余全部并行派给 subagent。

| 角色 | 做什么 | 禁止 |
|---|---|---|
| 主 agent | 定方向/方案、拆线索、调度、**独占重资源操作**、综合、实现与验收 | 当消息转发器；任何空闲等待 |
| subagent | 一条独立线索的调研/取证（只读为主） | 抢共享资源、跑 e2e/压测/部署/重启、sleep/task_wait、相互协调 |

## 铁律

1. **禁止 `sleep`**（前台/后台/循环里都不行）→ 要等就用 `Shell(background: true)`。
2. **禁止 `task_wait`**（唯一例外：用户明确要求等它）。
3. **禁止反复 poll 后台任务状态**：`task_status` 只在确实要判断"现在能不能用它的结果"时查一次。连续/定时反复查 = 变相 sleep，**等完成通知即可**。
4. **任何时刻 ~3 个 subagent 在飞**：收到完成通知**当轮回填**。没有独立线索就少派 —— 不硬凑、不派有依赖的任务。
5. **重资源操作只由主 agent 串行执行**：机器/GPU、端口、共享服务、部署/重启、e2e/压测、大构建。
6. **派发前查冲突**：在飞任务的资源白名单（机器/GPU/端口/目录/分支/服务）任一维度不得两人同时持有。

## 循环

```
定方向 → 切 N 条【互相独立】的线索（问题 / Done 判据 / 资源白名单）
→ 派发填满 3 槽（冲突检查）→ 主 agent 同时做自己的高价值工作（绝不空闲）
→ 完成通知到达：提炼结论 → 判断是否换角度 → 立即回填
→ 证据足够：自己实现/整合/验收（要并行实现 → 按不重叠 scope 派）
```

## Subagent 任务契约（缺一不可）

1. **问题清单** —— 要回答什么（不是"看看 X"）。
2. **Done 判据** —— 可验证。
3. **输出格式** —— 结论 / 证据（`file:line`、命令、日志）/ 未决问题。
4. **资源白名单** —— 只能用这些机器/端口/目录/分支；禁止起常驻服务。
5. **禁止事项（复述）** —— sleep、task_wait、反复 poll 状态、改共享资源、重启服务、跑 e2e/压测、与其他 subagent 通信。
6. **只读优先** —— 要写代码 → worktree 隔离 + 独占目录，一个目录/分支同时只允许一个写者。
7. **Feature guard（强制）** —— 新行为必须带可切换开关，交付声明 `guard 名 / 默认值 / 开 / 关 / 验证命令`；没有 guard 的行为改动视为未完成。

## Feature guard —— 并行改动的 bisect 前提

并行快速迭代下，改动没有开关就只能 revert 一大坨、无法定位是谁的哪一处。

- 单一开关控整条链路，检查点在**入口一处**
- 定义与默认值只在**一处**（config / settings / 常量）
- 实验性 → 默认 off（验证后打开）；低风险 → 可默认 on，但留 kill switch
- 启动打印开关状态
- on/off 两条路径都有测试，**off 不得回归**
- 验证用 on/off 对照：on 有新行为，off 与旧行为一致
- 稳定后**删掉** guard（或按项目策略固化为长期 kill switch），不允许堆积

主 agent 用法：现象回归 → 配置层逐个关开关（不改代码）→ 二分定位到功能 → 定位到 subagent/变更 → 修完重开复测。

## 主 agent 的方向时间

每轮回填后先想一轮再动手：假设是否被推翻？哪条线索价值最高？有没有更省的判别实验？该不该收敛？

向用户**阶段性同步**（方向 + 关键证据 + 下一步），不要每完成一个 subagent 就刷屏。

## 反模式

- `sleep` 等编译/部署；`task_wait` 等 subagent；**反复 poll 状态** —— 都是空转
- 一次派 6-8 个 subagent（冲突面爆炸、重复探索）
- 派有依赖的任务（是排队不是并行）
- 让 subagent 跑 e2e/压测/部署/重启（并发破坏共享资源）
- subagent 之间互相协调（调度权必须唯一）
- 并行改动没有 guard（无法二分定位）
- 把 subagent 原始长输出全量读进上下文（只读结论 + 证据）

## 何时不用

单点小任务、强串行流水线、需高频往返同一资源的调试 —— 自己做更快。

## 示例：性能定位

```
定方向：长 turn 卡顿 → 切 3 条只读线索（渲染链路 / 状态机派生层 / 性能守护测试盲区）
主 agent 同时：跑带 trace 的真实复现（独占浏览器 + 端口）
→ 通知回收 → 综合 → 定根因 → 自己修（或派不重叠 scope 的实现）
→ 自己跑验收（e2e 独占串行）
```
